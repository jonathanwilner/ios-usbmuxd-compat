# Security policy

This reference implementation is pre-1.0. Security fixes target the current
main branch. It has not received an independent security audit.

Before public hosting, the repository owner should enable GitHub private
vulnerability reporting. Use the repository Security tab to report a suspected
vulnerability privately. If private reporting is unavailable, open an issue
requesting a private contact without exploit details or sensitive files.

Report privilege escalation, unsafe path handling, unintended daemon activation,
configuration loss and information disclosure. Include a minimal synthetic
reproduction and affected version. Never attach real pairing records or keys.

See [the security model](docs/security-model.md) for authorization boundaries.
